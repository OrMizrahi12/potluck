# What stays human

A **one-way door** is an act a revert PR can't undo: its effect lands outside the repo, on production, on real people's data or in public, before a revert could follow it. Only a human walks through one. An agent prepares the change, and a human makes the call.

A revert removes the file, but the schema change stays applied. ## Ready-for-human tickets

`claude-build.yml` refuses any issue labelled `ready-for-human`, whether or not it's a one-way door. Each ticket's reason line maps to the table:

- **#2** (closed) and **#12**: settings and secrets.
- **#11**: copying production data out (the backup and its recipient), production secrets, restoring a backup, and the launch.
- **#32**: merging a migration that changes a constraint.
- **#34**: seeding production.
- **#37**: copying production data, and the link shape.
- **#31** (settlement cap) and **#33** (glossary words) are human judgement calls but not one-way doors: a revert undoes them.

## Adding a door

Add a row. If files sit behind the door, add an `Edit(/path)` deny for them to `--disallowedTools` in `claude-build.yml`, and prove it the way the first deny was proved: a headless `claude -p` run on a scratch copy with the workflow's own `claude_args`, where the new path is denied and an ordinary `src/` file is still allowed.
